## Findings (most severe first)

### 1. A clone whose connect is in flight survives reload or config prune. Confirmed by repro.
- **Where:** `tools/mcp_tool_project_scope.py` `_server_for_call` (the insert after `_connect_clone`), and
  `tools/mcp_tool_lifecycle.py` (`pop_clones` in `shutdown_mcp_servers`).
- **Defect:** `pop_clones` sees only clones that are already inserted. A thread still inside `_connect_clone`
  inserts its clone after teardown, without checking that the baseline is still live.
- **Effect:** the server is torn down while project P's first call is connecting, and the clone is inserted
  afterwards with a live child and no baseline.
  - Server removed from config: the child leaks until the process exits.
  - Server re-registered: project P keeps the old config's child until that clone is evicted.
- **Fix:** at insert, under `_core._lock`, require `_core._servers.get(key) is baseline`. Otherwise shut the new
  clone down (off-lock) and return None.
- **Repro:** see the appendix. After the prune it prints `baseline present: False ... alive: [True]`.

### 2. Clones run the events refresh loop. Confirmed by reading.
- **Where:** `tools/mcp_tool_transport.py` `_run_stdio` (`_events.start_refresh_task(self)`) and
  `tools/mcp_tool_events.py` `run_refresh_loop`. `start_refresh_task` runs whenever
  `events_enabled(server._config)` is true, and a clone copies the baseline config.
- **Effect:** each clone force-resubscribes every webhook route for the server name. A terminal refusal from a
  clone's child (-32023, -32024, -32026 or -32602) deletes the route (`_write_route(route_name, None)`) for
  every project. Even without a refusal, each clone resubscribes, so the same event arrives several times and
  starts several unattended agent runs.
- **Fix:** never start the refresh task on a clone (`if self._scoped_cwd`). Route the event handlers
  (`mcp_tool_events._make_events_handler`) to the baseline, not to a clone.

### 3. `rekey_unscoped_connections` orphans clones. Confirmed by reading.
- **Where:** `tools/mcp_tool_scope.py` `rekey_unscoped_connections`.
- **Defect:** the keyed ledgers move from bare names to `(scope, name)`. `_scoped_servers`,
  `_scoped_connect_locks` and `_scoped_active_calls` keep their `(name, cwd)` keys.
- **Effect:** the gateway turns on multiplexing at runtime (`gateway/run_profile_reconcile.py`). Later calls
  create new clones keyed `((scope, name), cwd)`. The old clones (up to 8 live children per server) are never
  reused or evicted, because eviction filters on `k[0] == key`. A scoped `/reload-mcp` never pops them either;
  only a wildcard shutdown does.
- **Fix:** rekey the three sidecar dicts inside `rekey_unscoped_connections`. Count leases on the clone object
  (a counter attribute) instead of by key, so in-flight releases stay balanced across a rekey or a reload that
  reuses a key.

### 4. A failed connect drops the single-flight lock while others wait on it. Plausible.
- **Where:** `tools/mcp_tool_project_scope.py` `_server_for_call`, the `_scoped_connect_locks.pop` after a
  failed connect.
- **Effect:** T1 fails and pops lock L while T2 is blocked on L. T2 connects, and at the same time T3 gets a
  fresh lock from `setdefault` and connects too. Two clones are created, the second insert overwrites the
  first, and the first child leaks.
- **Fix:** keep the lock on failure; eviction and `pop_clones` already bound the dict. Also make the insert a
  `setdefault` that shuts down the losing clone.

### 5. A failing clone has no connect cooldown and trips the breaker for every project. Confirmed by reading.
- **Where:** `tools/mcp_tool_project_scope.py` `_connect_clone` and `tools/mcp_tool_handlers.py`
  `_acquire_call_server`.
- **Defect:** baselines have `_connect_cooldown_active`; clones have nothing equivalent.
- **Effect:** every call from a broken project tries a full spawn, which waits up to `connect_timeout + 5`
  (65 s by default). Callers waiting on the connect lock retry one after another, and the wait cannot be
  interrupted. Each failure bumps the baseline's breaker, so 3 failures in project B pause the server for 60 s
  in every project.
- **Fix:** a per-clone-key failure cooldown with backoff, in the sidecar module.

### 6. Eviction shuts the victim down on the caller's thread, and an interrupt can cut it short. Plausible.
- **Where:** `tools/mcp_tool_project_scope.py` `_evict_idle_overflow`.
- **Effect:** the first call in the 9th project blocks for up to 15 s on another project's shutdown.
  `_run_on_mcp_loop` honours `is_interrupted()`. If the cancel lands before `shutdown()` starts, the victim has
  already been popped but its child stays alive.
- **Fix:** fire and forget with `safe_schedule_threadsafe(clone.shutdown(), loop)`, as `shutdown_mcp_servers`
  does.

### 7. The slash worker's `TERMINAL_CWD` pin can be overwritten by config. Plausible.
- **Where:** `tui_gateway/slash_worker_client.py`.
- **Defect:** the worker runs `import cli`, which goes through `load_hermes_dotenv`,
  `_reapply_terminal_config_bridge` and `apply_terminal_config_to_env`. When config.yaml sets `terminal.cwd`
  explicitly, `should_override` rewrites `TERMINAL_CWD`.
- **Effect:** the worker's stdio MCP children spawn in the config dir. `Popen(cwd=)` does not help, because
  `resolve_context_cwd` prefers `TERMINAL_CWD`.
- **Fix:** pass the project to the worker (an argv flag on `tui_gateway.slash_worker`). Re-pin it, or call
  `set_session_cwd`, after `cli` is imported. Verify with a test that sets `terminal.cwd` in config.

### 8. Smaller issues. Confirmed by reading.
- **Extra persist during `workspace.move`:** in `tui_gateway/session_workdir.py` `_move_session_cwd`,
  `before = _local_session_process_cwd(session)` goes through `_display_session_cwd`. That heals a dead cwd and
  writes the healed ancestor to the DB, with a git-meta probe. In `session.workspace.move` this runs just after
  the `replace_git_meta=True` write. The final state is correct, but there is a spurious intermediate persist.
  Fix: compare the raw `session.get("cwd")` values.
- **`cwd: null` opts out of cloning:** `tools/mcp_tool_project_scope.py` `_clone_cwd` uses `"cwd" in config`,
  but `_stdio_launch` treats `cwd: null` as unset. Fix: use `config.get("cwd") is not None`.
- **Remote backends:** `_caller_cwd` has no remote-backend check, unlike the slash-worker side. A docker or ssh
  session whose container cwd is missing on the host logs a "configured working directory does not exist"
  WARNING on every stdio call. If the path happens to exist on the host, a clone spawns in an unrelated host
  dir. Fix: skip cloning when the caller's terminal backend is not local.
- **Docs:** `website/docs/user-guide/features/mcp.md` says "up to 8 per server". The real limit is 8 clones
  plus the baseline, so 9 processes. Reword it.

## Checked and found correct

- **No double acquire of the non-reentrant `_core._lock`:** `_lease` and `pop_clones` run under it without
  re-locking. The connect and the eviction shutdown run outside it.
- **Leases:** acquire and release are balanced, with several leases per handler included. Release is in a
  `finally`, and all three handler factories are wrapped.
- **Tool schemas and trust state:** clones never touch them. The discovery guard is doubled (`_scoped_cwd` plus
  the `owned`/`_ready` check), `_refresh_tools` is guarded, and park and shutdown deregister nothing. The only
  name-keyed write from a clone is the breaker reset, which is the known deviation.
- **Recovery:** retries reuse the captured clone, and recovery lookups resolve the same clone on the same
  thread. A recycled (idle-timeout) clone is woken, because the clone is picked before the recycled check.
- **Servers that never clone:** HTTP, any server with an explicit `cwd`, and a gateway whose sessions sit in
  its `TERMINAL_CWD`, which is tested.
- **Teardown:** every path goes through `shutdown_mcp_servers` (reload, prune and reconcile, profile delete and
  rename, session-local MCP, gateway and CLI exit). Finding 1 is the timing exception.
- **Slash worker on remote backends and missing dirs:** it keeps the gateway cwd, and it restarts only on a
  real move.

## Side note (not part of this change)

`asyncio.run_coroutine_threadsafe` does copy the caller's context: `call_soon_threadsafe` captures it on the
calling thread. The reviewer verified this with a script. The comment in `tools/mcp_tool_loop.py`
`_run_on_mcp_loop` claiming otherwise is wrong. In practice a lazily connected baseline spawns in its first
caller's session cwd, which `_spawn_cwd` already handles. This is a candidate for a separate small fix, so it
stays out of this PR.

## Appendix: repro for finding 1

Drop this into a pytest file in the worktree (it imports the new test module) and run it with
`scripts/run_tests.sh <file> -s`.

```python
import sys, threading, time
from tests.tools.test_mcp_project_scope import _PROBE, _call, _clones

SLOW = _PROBE.replace('if method == "initialize":', 'if method == "initialize":\n        if os.path.basename(START) == "slow": time.sleep(3)')

def test_reload_during_clone_connect_leaks(tmp_path):
    from tools import mcp_tool
    from tools.mcp_tool_discovery import register_mcp_servers
    from tools.mcp_tool_lifecycle import shutdown_mcp_servers, _kill_orphaned_mcp_children
    (tmp_path / "probe.py").write_text(SLOW)
    (tmp_path / "slow").mkdir()
    register_mcp_servers({"keeper": {"command": sys.executable, "args": [str(tmp_path / "probe.py")], "connect_timeout": 30, "timeout": 30}, "racer": {"command": sys.executable, "args": [str(tmp_path / "probe.py")], "connect_timeout": 30, "timeout": 30}})
    assert "racer" in mcp_tool._servers
    out = {}
    t = threading.Thread(target=lambda: out.update(r=_call("racer", cwd=str(tmp_path / "slow"))))
    t.start()
    time.sleep(1.0)  # clone connect in flight
    shutdown_mcp_servers(scope=None, names={"racer"})
    t.join(30)
    try:
        leaked = _clones("racer")
        print("baseline present:", "racer" in mcp_tool._servers, "clones after prune:", list(leaked),
              "alive:", [s.session is not None for s in leaked.values()])
        assert not leaked, "a clone connected during the prune survived it"
    finally:
        shutdown_mcp_servers()
        _kill_orphaned_mcp_children(include_active=True)
```
